# T433: bounded pack activation atomicity

This change joins one pack activation/replacement to the existing projector. It is not
the M8 configuration-generation model and does not introduce another projector or decider.

## Publication boundary

The installer validates caller authority first and captures the expected old active version.
Under one pack-projection write lease it enlists every configured participant, clones
process-local registry roots, and opens one SQLite transaction when durable stores participate.
It checks the expected old version again, stages ownership/pointer/admission changes, and runs
the existing projector and retirements once against those unpublished roots.

Any refusal, invalid/deferred supported definition, platform incompatibility, exception, or
cancellation discards the clones and rolls back SQLite. The installed draft is retained.
The old objects are restored by reference, not regenerated by compensating projection.
Successful preparation completes admission evidence and commits SQLite before releasing the
write lease. Participating readers cannot observe the sequential private root assignments.
Cleanup after a successful durable commit cannot report activation as refused; notification
failures are diagnostics on a committed outcome. Observers run once after releasing the lease.

The AsyncLocal carries only reentrant lease ownership. Staged domain state lives on explicitly
enlisted participant instances. Projection is sequential: child work must not inherit and
concurrently exercise a writer's reentrant ownership. Independent request contexts take leases.

The reader canary exercises 19 real reader surfaces from independent execution contexts
while activation holds its write lease. It fails if any exercised reader returns before release.
New projected stores must join this inventory, implement staging, and add a reader canary;
an unrecognized configured participant fails closed instead of silently escaping the transaction.

## Durable and crash boundary

Pack state and authorization configuration use different EF contexts over the same encrypted
local-node SQLite file. PackProjectionSqliteUnit enlists both in one physical connection and
transaction; a different database is refused. Encrypted-file reopen tests prove old pointer
and old definition/binding revision before commit, and both new values after commit.

Current host form/workflow composition uses the existing in-memory entity implementation.
This change does not invent durable form storage: an alternate entity implementation must
implement the participant contract and join the same durable unit before it can be activated.
Completed pack admission is re-projected by the existing startup service to rebuild volatile
registries. Crash before SQLite commit retains old durable state; crash after commit retains
the complete new durable pack/config state and rebuilds runtime registries from those seeds.
This is not a cross-process memory transaction, and readiness must continue to gate consumers
during startup restoration. Explicit deactivation and legacy-incomplete-admission reconciliation
retain their existing lifecycle semantics; replacement retirements run inside this activation unit.
