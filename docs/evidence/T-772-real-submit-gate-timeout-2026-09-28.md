# T-772 real submit-gate timeout propagation, scoped mutation evidence

The public seam is the production `IFormEngine.SaveWithReceiptAsync` composed by `AddTestNodeForms` with a published form and a compiling `restrict.active` validation rule. The new test first proves the rule validates normally, then arms a test clock to cancel the request token at the graph's clock read, after authorization and definition lookup. `SaveWithReceiptAsync` propagates the real graph's `RuleEngineTimeoutException` instead of returning a validation verdict or reaching persistence. The first attempt with an already-cancelled token failed at the authorization gate with `OperationCanceledException` and was test setup failure, not a useful behavioral red. The corrected focused test passed; the affected host test project passed 4,524 tests with 22 skipped. No production code changed.

Repository-pinned Stryker.NET 5.0.0 used source project `Harborline.Foundation.Forms.Engine.csproj`, the pinned SDK's `MSBuild.exe`, default per-test coverage analysis, and `FullyQualifiedName~Submit_gate_propagates_a_real_rule_graph_timeout_instead_of_saving`. The first selected-file run targeted `**/SubmitValidationGate.cs{5325..5696}`; the one narrower follow-up targeted `**/FormEngine.cs{43352..43519}` at the gate call. Both selected the one public test, but Stryker's safe mode excluded `SubmitValidationGate.Evaluate` after instrumentation compile errors elsewhere in that method; the call-site span produced no mutation operators. Each run generated 1,302 mutants, marked 436 CompileError and 866 Ignored, and tested zero. Their raw [gate report](mutation/t772-api-real-submit-gate-initial-2026-09-28.json) and [call-site report](mutation/t772-api-real-submit-call-2026-09-28.json) each have SHA-256 `9758E8AB55DF7E1152C8B2D73FFDE64F5E1C889B426B450F92FECC0A09717A78`. No mutation score or Stryker kill is claimed. Do not retry either run unchanged.

After the ordinary suite was green and Stryker could not instrument this seam, a controlled manual mutation changed the gate branch from `if (hasRules)` to `if (false && hasRules)`. The focused public test failed for a behavioral reason: instead of the expected `RuleEngineTimeoutException`, the bypassed write reached `UnusedFieldEncryptor` and threw `InvalidOperationException` with “A refused write must never reach field encryption.” The source was restored with no production diff, and the focused test passed again. This probe shows the test detects bypass of the real gate; it is separate from the Stryker result below.

The pattern-bound locals `guard`, `compileCode` and `validity` in `SubmitValidationGate.Evaluate` were then rewritten as equivalent explicit locals to avoid Stryker's definite-assignment instrumentation errors. `RuleFailClosedTests` passed 18/18 and the affected host project passed 4,524 with 22 skipped after this refactor. A Basic-level run on `**/SubmitValidationGate.cs{5325..5338}` still tested zero mutants: its only selected block-removal mutation was a CompileError. The raw [Basic report](mutation/t772-api-real-submit-branch-basic-2026-09-28.json) has SHA-256 `088DBC766E472A1DF2AA351ABFC26E79D264DE352B26B8875A0921AA5BED814D`; it is not a behavioral check. The one changed Standard-level follow-up used `**/SubmitValidationGate.cs{5325..5696}`, the same exact public test filter and default per-test coverage analysis. It tested five mutants: four Killed by `Submit_gate_propagates_a_real_rule_graph_timeout_instead_of_saving` (report test ID `58f49abc-553d-5603-5c53-426de505a3b5`) and one Survived. The kills include negating `hasRules` (1061), suppressing `compiled.RuleCount > 0` (1064 and 1066), and removing graph evaluation (1067). Survivor 1065 changes `RuleCount > 0` to `>= 0`; it enters the graph only when compilation produced zero rules, so it cannot bypass or alter evaluation of a compiling rule and does not violate this timeout contract. The raw [Standard report](mutation/t772-api-real-submit-branch-standard-2026-09-28.json) has SHA-256 `19E00B805717F3A5BD466F62CCAB8D56860E7BCFD6221B665EEBD84ECA847B2C`. This is scoped mutation evidence for the real gate branch, not a certificate for the entire form engine.
