# T-946 K4 route fence evidence

Tested from API parent commit `213b55b24603008e48fd8bf39e7e4018cfcd1b84` with the T-946 source and tests in this commit, .NET SDK `11.0.100-rc.1.26425.128` and Stryker.NET `5.0.0`.

The new live route registry test walks every method and route in all six supported production host profiles, expanding wildcard methods to common HTTP verbs. No production route has a tenant-named placeholder; the test fails if one is added. A synthetic registry probes four tenant placeholder spellings on live routes. Query, header, route, JSON body, form field and multipart file-field injections receive 400 where those sites apply. `/api/session/select` and `/api/session/switch` accept only their intended root `tenantId` choice on POST; query, header and nested body injections still receive 400. This narrow exception awaits a control design ruling because DES-0029 K4 and L005 literally say every request carrying a tenant identifier receives 400. Account-setup invitation acceptance now derives its tenant from the stored invitation, and its live route tests pass without a caller tenant field.

The red-first control observed 403 instead of 400 on an unfenced route. Removing both `CallerTenantIdentifierFence.Use` call sites again made the new test fail; both calls were restored. A focused Stryker run against `Health/CallerTenantIdentifierFence.cs` with `FullyQualifiedName~CallerTenantIdentifierFenceTests` killed 44 of 49 mutants (89.80%) with zero timeouts or errors. The only survivors, IDs 33049, 33053, 33056, 33074 and 33084, change `ConfigureAwait(false)` to `true` and do not alter the tested HTTP behavior. The raw JSON report is in the local ignored path `apps/local-node-host/tests/.stryker/t946-reviewed/reports/mutation-report.json` (SHA-256 `AE9828F047C46955DC480E760071FC91B2E66C3E9D919110EC505774A9FD7FAB`).

The full host suite passed on the reviewed source: 4,515 passed, 22 skipped, zero failed (4,537 total, 6 minutes 22 seconds). The local ignored TRX is `apps/local-node-host/tests/TestResults/t946-reviewed-full.trx` (SHA-256 `247C05C132E1B947129BA1254A13CB979E8E624C182922E20106B894EC8A043F`). The unrelated localization target test needs the local Release build of `tooling/Harborline.Tooling.LocalizationXliff/Harborline.Tooling.LocalizationXliff.csproj`; that build passed before this run. T-946 remains open until the selection exception is reconciled with control design and the raw mutation report is attached to a durable delivery run.

## Malformed-body refusal follow-through

At the same live route seam, one malformed multipart body and one malformed JSON body each returned 200 when the focused test expected 400. After the two parse-error catches threw `BadHttpRequestException`, the focused class passed 3/3. The final ordinary local-node-host test project passed 4,517 tests with 22 skipped and zero failed; its local TRX is `apps/local-node-host/tests/TestResults/t946-malformed-full.trx` (SHA-256 `D0D45367FEFABDF4EDA061FB14D7019D4538AEBCAF5589C538ED818839317CF7`). These two cases prove a narrow malformed-body refusal, not all of ledger L985 or CK4.

Stryker.NET 5.0.0 used a temporary ignored configuration with `mutate: ["Health/CallerTenantIdentifierFence.cs"]`, the `CallerTenantIdentifierFenceTests` test-case filter and default per-test coverage analysis. The final scoped run tested 51 fence-file mutants: 44 Killed, 7 Survived, 0 Timeout and 0 runtime Error (86.27%). Removing the multipart throw (mutant 33079) and JSON throw (33089) was Killed by the corresponding parameterized malformed-body test case. Five survivors change `ConfigureAwait(false)` to `true`; two change only the exception message text, outside the HTTP 400 contract. Two additional fence-file mutants had compile errors, and 11 were ignored; neither counts as a kill. The raw local JSON is `apps/local-node-host/tests/.stryker/t946-malformed-filtered/reports/mutation-report.json` (SHA-256 `F9AD71515C1110FCE27A73B769B69CE73A6AD68A6DE2C184EBD4D56600AEE474`). This report is scoped to the fence and test class, not a whole-host mutation certificate.

## Identifier spelling follow-through, pending mutation verification

The live registry test added `X-Tenant-Identifier` to its injected spellings. Before the production edit, the query-key case with that spelling reached `/api/local-node/journal-entries` and returned 200 where the test expected 400; the registry test also exercises the same spelling as a header and JSON body key after the edit. Adding `xtenantidentifier` to the shared key matcher made the focused class pass 3/3. The affected local-node-host test project then passed 4,517 tests with 22 skipped and zero failed; the local TRX is `apps/local-node-host/tests/TestResults/t946-header-full.trx` (SHA-256 `DE9BA0799FDA45B261CE5FBDB9068F849ED03497A76BB7E13D96E562E042149C`). No refactor was needed.
