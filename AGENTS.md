# Agent guide — harborline-api

## Mutation testing (Stryker.NET)

Read this before you add or change a test project's Stryker setup, or claim mutation evidence for a ticket. `eng/mutation-report.mjs` is the entry point; its header documents `--check`, PR mode and `--full`. Per-project scores and floors live in `eng/baselines/mutation-baseline.json`.

- **`--only` takes the exact test project path.** Pass the repository-relative `.csproj` path, for example `--only packages/foundation-localfirst/tests/Harborline.Foundation.LocalFirst.Tests.csproj`. A name fragment matches nothing and prints an empty table.
- **Linked worktrees need `--full`.** Since-mode in a linked worktree marks every mutant Ignored and exits 0, so use `--full --only <path>` there, or run from a plain clone.
- **One config mutates one direct reference.** A test project's config mutates exactly one project that test project references directly; Stryker cannot mutate a project reached only transitively. To mutate a package whose tests live in another test project, add a direct `ProjectReference` there, as the host tests do for `packages/foundation-authorization`.
- **Lane evidence uses `--scoped`.** `node eng/mutation-report.mjs --only apps/local-node-host/tests/tests.csproj --scoped '**/Health/AssetRegistryRoutes.cs' --filter 'FullyQualifiedName~AssetRegistryRouteTests'` mutates one file and runs only the filtered tests; add `--project Harborline.Foundation.Authorization.csproj` to mutate a directly referenced package instead of the config's project. It works in a linked worktree, prints each file's counts and survivors, and fails when no mutant was tested. The report still lands in `.stryker/` and stays untracked.
- **A `{a..b}` suffix on a mutate glob is a character span, not a line range.** `AuthorizationGate.cs{94..126}` selects characters 94 to 126, which is the usings, so every mutant is Ignored. Mutate the whole file and read the lines you need from the report.
- **CompileError counts are project-wide rollbacks.** Stryker compiles every mutant of the project, then rolls back the ones that fail to compile (pattern variables such as `is { } x` duplicated by instrumentation, `Count()` to `Sum()` on a method group). They are CompileError whatever `mutate` says, so "all mutants resulted in compile errors" with zero tested means the glob matched nothing, not a toolchain fault.
- **Stryker makes no bypass mutant for an `if (await Gate(...) is { } denied) return denied;` guard.** Its Equality mutant (`is not { }`) leaves `denied` unassigned and is rolled back as CompileError, and it makes no block removal for a one-statement `if`. For such a guard, the killed mutants are the permission and record strings; the guard-removal evidence stays a manual removal (T-724 ruling 35), as T-974 recorded.
- **Keep whole-host reports out of the tracked tree.** A report from the host test project is about 10 MB and embeds every host test source. The retired-prefix scan, the identity-r3 era-token scan and the quality gate's input-size limit all reject it. Archive the raw report on an `archive/*` branch, and pin its SHA-256 in the evidence note, as `docs/evidence/T-772-real-submit-gate-timeout-2026-09-28.md` does.
- **The report is the evidence, not the exit code.** Stryker can exit 0 having mutated nothing. Read the JSON report and name the killing test for each mutant a ticket lists (T-724 ruling 35). Mutant ids change between runs, so match survivors by file, line and mutator.
- **Run Stryker natively.** Inside the Codex sandbox its restore fails for lack of network; record that and leave the run to the controller.
