# Adversarial Review Round 3 — Skeptical Implementer

**Date:** 2026-06-06
**Perspective:** Skeptical Implementer — technical feasibility reviewer
**Scope:** Layout (18 components) + Overlays (10 components) + Utility (12 files: 5 stubs + RoleGate full) + ESignatureField (4 contracts)
**Prior rounds read:** Yes — rounds 1+2 findings reviewed first; SI-1 through SI-14 + FV/AI/GAP/DIS/UPF findings noted as already-applied

## Summary

The Layout + Overlays + Utility + ESignatureField contract set is broadly implementable but carries **8 critical-or-high technical infeasibility issues that will produce silent visual/behavioural bugs** if built as written. The most load-bearing: (1) Drawer chained Tailwind v3 data-variants that won't compile as written, (2) AppLayout sticky AppBar geometry that violates CSS sticky-containment rules, (3) Card horizontal-orientation contradictions between Semantic example and prose, (4) Tour spotlight pointer-events needing a non-trivial DOM split not described, (5) Tour Tab key collision between Interaction (advance step) and Accessibility (focus trap), and (6) Popup outside-click racing with its own trigger. All 6 critical items are forward-spec areas that will surface immediately when implementation starts.

## Findings

| ID | Severity | Component(s) | Issue | Recommended fix |
|---|---|---|---|---|
| SI3-1 | Critical | Drawer (Styling §3.2) | Chained Tailwind v3 variants `data-[side=right]:data-[state=open]:slide-in-from-right` — v3's variant compiler does NOT support arbitrary attribute-variant chaining. The two `data-[…]:` selectors collapse into one at compile time; the other is dropped silently. Result: animations either always fire or never fire, browser-dependent. | Either (a) precompute side-dependent classes in JS and emit a single `data-[state=open]:slide-in-from-right` per branch, or (b) explicitly pin Tailwind v4 (which supports nested variants natively) in the Styling contract. |
| SI3-2 | Critical | AppLayout (Styling §3.1 + §3.3) | Sticky AppBar (`position: sticky; top: 0`) is a **sibling** of `<main class="overflow-y-auto">`, not a child. CSS sticky only sticks relative to the nearest scrolling ancestor — if AppBar is outside that scroller it behaves as `position: relative` and will not stick when the main panel scrolls. | Restructure §3.1 so AppBar is inside the same scroll container as main, OR change AppBar to `position: fixed` (the `headerFixed` prop already exists in Semantic) and document the top-padding compensation. |
| SI3-3 | Critical | Card (Semantic §3.8 + Styling §3.5) | Horizontal-orientation spec is internally inconsistent: §3.8 says `CardHeader` forms the left column, but the example places `<img>` as a direct child of `<Card>` outside any `CardHeader`. Separately, Styling §3.5 specifies `divide-y` for separators in horizontal mode — but with `flex-row` layout, `divide-y` paints horizontal lines between rows (wrong; should be `divide-x`). | Pin rule in Semantic: in `horizontal` mode, CardHeader/CardContent/CardFooter form the L→R cells. In Styling §3.5, make the divide conditional: `divide-y` for vertical, `divide-x` for horizontal. |
| SI3-4 | Critical | Tour (Styling §1 + Interaction §4) | "Spotlight cutout in the mask + clicks pass through to the underlying element" is not achievable with `clip-path` alone. CSS `clip-path` removes only paint; the cut-out region still receives pointer events from the mask element. | Either (a) describe the four-rectangle donut layout explicitly in Styling §1 + Interaction §4 (pointer-events-blocking strips tiled around the target with `pointer-events: none` on the centre), or (b) make the mask fully blocking and treat "click target inside cutout to advance" as a documented next-version feature. |
| SI3-5 | Critical | Tour (Interaction §5 vs Accessibility §6) | Tab-key semantics contradict: Interaction §5 says "Tab: advance to next step"; Accessibility §6 says "Tab cycles within the popover (trapped)." Both cannot hold. Hijacking Tab also breaks WAI-ARIA `role="dialog" aria-modal="true"` focus-trap requirements. | Drop "Tab advances step" from Interaction §5; keep ArrowRight for advance. Add a note that Tab is reserved for focus-trap traversal and MUST NOT be intercepted. |
| SI3-6 | Critical | Popup (Interaction §2) | Outside-click uses a `mousedown` listener on `document` added on mount. This races with the trigger's own click handler: when the user clicks to open, the mousedown fires first → if popup mounts synchronously, the listener is already active to receive the same mousedown as it bubbles → popup closes immediately. Net result: popup either never opens or opens-then-closes in one click. | Add the listener in a `useEffect` with a microtask delay (`setTimeout(…, 0)` or `requestAnimationFrame`) so the opening click finishes propagating first. Document this pattern explicitly — it bites every implementer once. |
| SI3-7 | High | Tooltip (Semantic §2 + Accessibility §2/§4) | The "trigger receives `aria-describedby` linking to the always-rendered tooltip" pattern (RA-5 blocking note) requires `React.cloneElement(children, { 'aria-describedby': tooltipId })` — which the spec does not describe, has known pitfalls with forwarded refs, and breaks if `children` is a fragment or has multiple children. | Pin the `cloneElement` or Radix `Slot` pattern explicitly in Semantic §2: "wrapper clones its single child to inject `aria-describedby={tooltipId}`; throws in dev if `children` is not a single element." |
| SI3-8 | High | Carousel (Styling §2 + Semantic §3) | Slide track uses `transform: translateX(-${index * (100 / slidesPerView)}%)` with `gap` (pixels) on the same flex container. With positive gap, each slide is narrower than `100%/slidesPerView`, so cumulative drift of `index * gap` pixels accumulates as index increases. Visible misalignment after a few slides. | Either drop `gap` and use internal slide padding, or compute transform in pixels using `useRef` on container `offsetWidth`. |
| SI3-9 | High | Splitter (Interaction §2) | `setPointerCapture` AND `window.addEventListener('pointermove')` are used together. Pointer capture already routes all `pointermove`/`pointerup` to the capturing element — the window listener fires the handler twice per event, doubling drag deltas. Firefox honours both paths differently than Chromium. | Pick one: pointer capture is the modern path — drop the window listeners entirely. |
| SI3-10 | High | Window (Styling §5) | Title-bar buttons are `h-5 w-5` (20×20 px) — below WCAG 2.5.8 minimum target size of 24×24 px. Additionally, `pointerdown stopPropagation` on buttons (to prevent drag activation) can suppress focus migration in some browsers. | Bump hit area to `h-6 w-6` minimum or add `p-1` padding. Replace `stopPropagation` with an explicit check: `if (e.target === titleBar) startDrag()`. |
| SI3-11 | High | Window (duplicate) | Two Window components exist — `Layout/Window` (catalog #149, medium, v1) and `Overlays/Window` (catalog #147, planned). Near-identical contracts, both referencing the same impl path `packages/ui-react/src/components/layout/Window.tsx`. An implementer cannot determine which is canonical. | Consolidate to one Window entry (Overlays is the better home for a floating overlay). Demote the other to an alias-redirect stub. Update master catalog to remove duplicate. |
| SI3-12 | High | ESignatureField (Styling §5.2 Clear button) | Clear button uses `absolute top-1 right-1` but the parent panel container (§5.1) has no `relative` positioning. The button will position to the nearest positioned ancestor — likely the root ESignatureField container — floating to its upper-right corner instead of the canvas corner. | Add `relative` to the Draw-method panel container in §5.1, or wrap canvas + Clear button in a `relative` sub-container. |
| SI3-13 | High | ESignatureField (Interaction §4.1) | Typed-name → canvas image generation uses `ctx.font` with a cursive web font (Dancing Script). If the font hasn't loaded when `fillText` runs, browsers fall back silently to a system font. The on-screen preview (DOM render) shows the correct font; the captured image doesn't. Users cannot detect the discrepancy. | Add to Interaction §4.1: "MUST `await document.fonts.load('32px Dancing Script')` before calling `ctx.fillText`. If font fails to load, either fall back to SVG-text strategy or surface an error — do NOT silently capture with a fallback font." |
| SI3-14 | High | ESignatureField (Accessibility §3.2 canvas fallback) | `<canvas>…fallback text…</canvas>` is the historical AT fallback pattern, but Safari + VoiceOver does NOT reliably read canvas fallback content — often skipping the canvas entirely or reading only the role. The contract claims WCAG 1.1.1 compliance via this pattern; the claim is fragile. | Move instruction paragraph OUTSIDE the `<canvas>` to a sibling `<p>` referenced by `aria-describedby`. Note Safari+VoiceOver limitation in the gap table. |
| SI3-15 | Medium | Sheet vs Drawer (Styling overlay opacity) | Sheet uses `bg-black/80`; Drawer uses `bg-black/50`. Both are shadcn Sheet-pattern siblings. Two near-identical components with divergent overlay opacity — same category issue as OO-7 (Sonner vs Notification). | Pick one family-wide overlay opacity token (shadcn default is `bg-black/80`). Define it in `overlays.tokens.json`. |
| SI3-16 | Medium | DockManager (Styling §2) | Semantic layout diagram shows top/middle-row/bottom stacking with middle-row holding left + center + right side-by-side. Styling §1/§2 specifies individual zone classes but no "middle-row container" — left + center + right would stack vertically in the flex-col root, contradicting the layout diagram. | Add the missing row-3 `<div class="flex flex-1 overflow-hidden">` layer to §2, with left + center + right as children. |
| SI3-17 | Medium | Accordion (Semantic §3.5) | `<button role="button">` — `role="button"` is redundant on a native `<button>` and causes "button button" double-announcement in some AT. WAI-ARIA spec explicitly prohibits adding redundant roles to native elements. | Drop `role="button"`. Wrap `<button>` in `<h3>` (or parameterisable heading level via `as` prop) per WAI-ARIA Accordion pattern. |
| SI3-18 | Medium | Carousel (Interaction §3) | Auto-play uses `setInterval` recreated on every `go` function change via `useEffect`. With `go` as a non-memoised function, the interval thrashes every render — cleared and re-armed, producing actual cadence of 3000ms + N×frame_time. | Memoize `go` with `useCallback` and depend only on `[autoPlayInterval, isPaused]`, or use a ref-based pattern that doesn't depend on `go`'s identity. |
| SI3-19 | Medium | AppLayout (Styling §3.3) | `z-60` is referenced in the z-index strata table but is not a default Tailwind v3 utility (defaults end at `z-50`). Without `theme.zIndex` extension in `tailwind.config.js`, `z-60` silently no-ops and Toast may not stack above Dialog. | Use `z-[60]` (arbitrary value, works in v3) or note that consumers must extend `tailwind.config.js` with `zIndex: { '60': '60' }`. |
| SI3-20 | Medium | ScrollArea (Styling §3) | Horizontal scrollbar recipe includes `flex-col` — semantically wrong for a horizontal scrollbar (should be `flex-row` or no direction). Causes unpredictable thumb sizing in Safari + Firefox where height-constrained `flex-col` behaves oddly. | Change horizontal scrollbar to `flex-row` (or remove the flex direction). Verify against Radix ScrollArea defaults. |
| SI3-21 | Medium | ExpansionPanel (Semantic §4) | Header uses `<div role="button" tabIndex={0}>` — requires manual implementation of Space→click, disabled→tabIndex={-1}, and form semantics that native `<button>` provides automatically. The Space→preventDefault dance is not described. | Switch to native `<button>`. If button-in-button nesting is a concern in a specific use case, document it explicitly and describe the Space-preventDefault requirement. |
| SI3-22 | Medium | Splitter (Accessibility §2) | `role="separator"` on a resizable divider without `aria-valuenow`/`aria-valuemin`/`aria-valuemax`/`aria-orientation`. ARIA spec requires values on resizable separators. AT users hear "separator" with no size context. | Add `aria-valuenow={currentPercent}` + `aria-valuemin={0}` + `aria-valuemax={100}` + `aria-orientation` to the divider element even if keyboard resize is deferred. |
| SI3-23 | Low | AnimationContainer (See Also) | Cross-reference `[Carousel](../DataDisplay/Carousel.Interaction.md)` uses wrong path — Carousel is in `Layout/`, not `DataDisplay/`. | Fix to `../Layout/Carousel.Interaction.md`. |
| SI3-24 | Low | Stepper (Semantic §3.5) | `role="list"` on `<div>` + `role="listitem"` on `<div>`. Safari + VoiceOver strips list semantics when explicit ARIA roles appear on non-native list elements. | Use native `<ol>`/`<li>` and drop redundant ARIA roles, or keep `<div>` and note Safari AT limitation. |
| SI3-25 | Low | Map (Styling §7) | Map marker popups use `<foreignObject>` to embed HTML inside SVG. Safari has long-standing bugs with `<foreignObject>` rendering — content frequently loses layout, pointer events, or fails at retina DPR. | Move popups outside SVG as absolutely positioned siblings over the map (derive position from `getBBox()` + container `getBoundingClientRect()`), or document the Safari limitation as accepted-risk. |
| SI3-26 | Low | ESignatureField (Styling §5.3) | `font-[var(--esig-type-font,'Dancing_Script,Brush_Script_MT,cursive')]` — multi-word font names with quotes inside Tailwind arbitrary bracket frequently fail compilation in v3. | Set font-family via `style={{ fontFamily: "var(--esig-type-font, 'Dancing Script', 'Brush Script MT', cursive)" }}` — inline style for this case; drop the Tailwind arbitrary class. |
| SI3-27 | Low | Drawer (Styling §3.2) | Canonical animation is "~300ms" but Tailwind's `animate-in`/`slide-in-from-right` defaults to ~200ms via `tailwindcss-animate`. `duration-300` is absent from the Tailwind recipe. | Add `duration-300` to the recipe in §3.2, or change the canonical duration to 200ms to match the library default. |
| SI3-28 | Low | Dialog (Styling §2.7) | Reduced-motion note says "fade stays at reduced duration OR an instant pop-in is also acceptable" — two valid implementations will diverge. | Pick one: keep fade at 75ms (subtle orientation aid) OR pop-in. Document the chosen value. |

## Closing assessment

Round 3 found fewer issues than Round 1 because most batch-31 fixes landed cleanly and the new in-scope forward-spec contracts (Drawer, AppLayout, ESignatureField, Tour) have cleaner authoring discipline than the wave-N reverse-specs. The 6 critical items are all forward-spec areas that will surface immediately when implementation starts and should be resolved in a batch-33 amendment before M2 implementation begins. Medium/low items can ride a debt queue.
