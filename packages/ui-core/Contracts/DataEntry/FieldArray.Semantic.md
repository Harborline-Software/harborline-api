# FieldArray — Semantic Contract

- **Component:** FieldArray
- **ADR 0017 family:** DataEntry
- **Contract type:** Semantic
- **Status:** Accepted
- **Companion contracts:** [Interaction](./FieldArray.Interaction.md) · [Accessibility](./FieldArray.Accessibility.md) · [Styling](./FieldArray.Styling.md)
- **Reference implementation:** `packages/ui-react/src/components/forms/FieldArray.tsx`
- **Catalog row:** #54 FieldArray (`app-priority: medium`, `library-scope: planned`)
- **Phase:** ADR 0017-A1 Phase M1 (wave-N extraction from shipping implementation)
- **Foundation:** none — hand-rolled dynamic field array wrapper

---

## 1. Component purpose

**FieldArray** — a headless render-prop utility for managing a dynamic list of form fields. Renders no DOM of its own; the caller decides all rendering via the `children` function.

---

## 2. Props

```typescript
interface FieldArrayField {
  id: string    // stable unique key for React; generated internally
}

interface FieldArrayOps {
  append: (value?: unknown) => void    // adds a new field entry
  remove: (index: number) => void      // removes field at index
  move: (from: number, to: number) => void  // moves field from one index to another
}

interface FieldArrayProps {
  name: string                                          // reserved; not used in M1
  children: (fields: FieldArrayField[], ops: FieldArrayOps) => React.ReactNode
  defaultValue?: unknown[]  // default: []; sets initial field count
}
```

---

## 3. Headless design

`FieldArray` renders `<>{children(fields, ops)}</>`. There are no wrapping elements, no styles, no ARIA attributes. All DOM structure comes from the caller.

---

## 4. Field identity

Each entry has a stable `id` string generated by an incrementing module-level counter (`field-1`, `field-2`, ...). The `id` is the only property on `FieldArrayField` — callers use it as React `key`.

---

## 5. defaultValue

`defaultValue` seeds the initial number of field entries. Each entry in `defaultValue` creates one `{ id: uid() }` entry. The actual values are not stored in `FieldArray` state — value management is the caller's responsibility.

---

## 6. name prop

`name` is accepted (for potential future form-library integration) but not used in M1.

---

## Wave UC-1 — FormController composition note

_Cross-reference: Form.Semantic §UC-1.3 (FormController props) + §UC-1.7 (field integration)._
_Status: Draft._

### UC-1.1 FieldArray inside FormController

`FieldArray` composes inside `FormController`'s render prop in the same way
it composes inside any host-managed form. `FormController` does not integrate
with `FieldArray` at the state layer — the host owns the array of values and
connects each element to the controller via `getValue` / `setValue`:

```tsx
<FormController
  initialValues={{ items: [{ label: '' }] }}
  onSubmit={handleSave}
>
  {({ getValue, setValue, errors }) => (
    <Form>
      <FieldArray
        name="items"
        defaultValue={getValue('items') as unknown[]}
      >
        {(fields, { append, remove }) =>
          fields.map((field, i) => (
            <FormField
              key={field.id}
              label={`Item ${i + 1}`}
              name={`items[${i}].label`}
              error={errors[`items[${i}].label` as never]}
            >
              <TextField
                name={`items[${i}].label`}
                value={
                  ((getValue('items') as Array<{ label: string }>)[i] ?? {})
                    .label ?? ''
                }
                onChange={v => {
                  const items = [
                    ...(getValue('items') as Array<{ label: string }>),
                  ]
                  items[i] = { ...items[i], label: v }
                  setValue('items', items)
                }}
                error={Boolean(errors[`items[${i}].label` as never])}
              />
            </FormField>
          ))
        }
      </FieldArray>
    </Form>
  )}
</FormController>
```

### UC-1.2 `name` prop future direction

When the UC-2 `Field` sub-component ships (Form.Semantic §UC-1.8 deferred
items), `FieldArray.name` will be used to scope the field path namespace for
nested `Field` children. The `name` prop is already accepted (M1 §6) so no
breaking change is needed at that point.
