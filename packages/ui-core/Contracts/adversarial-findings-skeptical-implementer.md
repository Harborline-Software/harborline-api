# Adversarial Review — Skeptical Implementer Perspective
Date: 2026-06-05

## Summary
Reviewed 4-contract sets for CircularGauge, StockChart, Chat (AI), Gantt, Upload, DatePicker, MultiSelect, Sparkline, and SankeyChart. The majority of contracts are implementable; most serious issues are in ARIA semantics (role misuse or ambiguity), CSS feasibility edge cases, and one underspecified streaming model. None of the findings are blockers for future-wave components, but three affect v1-priority components (DatePicker, Upload, MultiSelect).

---

## Findings

| Finding ID | Severity | Component(s) | Description | Suggested Fix |
|---|---|---|---|---|
| SI-1 | High | CircularGauge, LinearGauge, ArcGauge, RadialGauge | `role="meter"` is specified on the root element, but browsers and AT do not reliably support `aria-valuenow/min/max` on a non-native `<meter>` or `<div>`. ARIA spec requires `role="meter"` to be on a `progressbar`-compatible element; Jaws/NVDA map it via the `meter` role from ARIA 1.2, but Safari/VoiceOver do not fully support `role="meter"` on `<div>` or `<figure>` (as of mid-2025). The gauges would be silently unannounced on Safari/VoiceOver. Additionally, `aria-label` on `role="meter"` is valid but `aria-valuetext` (which announces the formatted numeric label, e.g. "72 km/h") is never specified — AT falls back to reading the raw `aria-valuenow` integer with no unit, which is semantically incomplete. | Add `aria-valuetext="{value} {unit}"` to every gauge's accessibility spec. For Safari/VoiceOver coverage, add a visually-hidden `<span>` with the formatted value as a belt-and-suspenders fallback (pattern used by many AT-compliant gauge implementations). Document the VoiceOver limitation as a Known Gap with severity Medium, not silently accepting it. |
| SI-2 | High | Gantt | `Gantt.Accessibility.md §2` specifies task bar role as `role="button" or role="gridcell"` — the "or" is unresolved. These two roles have entirely different keyboard semantics: `role="button"` gets `Space`/`Enter` activation; `role="gridcell"` implies it lives inside a `role="grid"` or `role="treegrid"` and participates in grid navigation (ArrowKey grid traversal). The timeline pane is NOT a `role="treegrid"` — the treegrid is on the left. A `role="gridcell"` floating in non-grid DOM is an ARIA hierarchy violation that ATs will handle unpredictably. A `role="button"` in the timeline pane is technically sound for `onTaskClick` but means the bar does not compose correctly with the treegrid left pane as a unified row. | Commit to `role="button"` for timeline task bars. They are activatable via `onTaskClick` which is button semantics, not grid navigation. Document that AT users navigate via the left-pane treegrid, not by tabbing through task bars (already partially covered in G-GANTT-A2). Remove the ambiguous "or" wording. |
| SI-3 | High | DatePicker | `DatePicker.Interaction.md §1` specifies `if (!e.currentTarget.contains(e.relatedTarget)) setOpen(false)` on blur as the close mechanism. This pattern is broken in React's synthetic event system on Safari: Safari does not focus non-interactive elements on click (no `relatedTarget` set on `<div>`, `<td>`, `<span>`). Clicking on a calendar day button outside the input-row area on Safari will set `relatedTarget = null`, causing `contains(null)` to return `false`, which closes the calendar before the day-click event fires — making date selection impossible on Safari. This is the most common real-world bug in custom date-picker implementations and is the same race documented in `G-MS4` (MultiSelect). This is already a v1 component with a shipping implementation. | Replace the `onBlur`+`contains(relatedTarget)` approach with a `useEffect` + `document.mousedown` (i.e., `onPointerDown` outside the popover ref) for close detection, which does not rely on `relatedTarget` being set. Alternatively, use `@radix-ui/react-popover`'s `onOpenChange` which handles this correctly. Document as a known bug to fix in M2 at minimum; it is likely already broken in Safari in the reference implementation. |
| SI-4 | Medium | Chat | `Chat.Accessibility.md §3` specifies the `aria-live="polite"` live region on the thread container and that AT announcements fire only on `status: 'streaming' → 'complete'` transition. This is the correct intent but the mechanism is underspecified in a way that creates an implementation trap: React updates `content` on every streaming chunk (many per second), and the container already has `aria-live="polite"` — so every React re-render of the container will trigger an AT announcement UNLESS the implementation explicitly removes the streaming message element from the live region's subtree during streaming and re-inserts it on `complete`. Simply saying "only re-announces when status transitions" is not a DOM behavior you get for free — you must architect it deliberately (e.g., render the streaming message outside the `aria-live` container and move it in on completion). The spec says nothing about how to achieve this, leaving implementers to discover the trap at runtime. | Add an implementation note to `Chat.Accessibility.md §3` describing the required DOM structure: during `status: 'streaming'`, the assistant message element should have `aria-live="off"` (or be rendered outside the `role="log"` live region), and be re-inserted / switched to `aria-live="polite"` only when `status` transitions to `complete`. Reference WCAG technique ARIA19 / the "swap region" pattern. |
| SI-5 | Medium | SankeyChart | `SankeyChart.Interaction.md §4` specifies: "links animate with path-length stroke draw over 600ms." In SVG, the path-draw animation via `stroke-dashoffset`/`stroke-dasharray` requires knowing the total path length at runtime (via `SVGGeometryElement.getTotalLength()`). For Bézier paths generated by the D3-Sankey layout algorithm, path length is only known after the SVG is mounted to the DOM and the layout pass completes. This means the animation cannot be purely CSS-declarative — it requires a `useEffect` + `requestAnimationFrame` cycle to read `getTotalLength()` and set inline `style` properties on each `<path>`. Tailwind utility classes cannot express this animation at all (it is not a standard `animate-*` class). The Styling contract says nothing about this animation mechanism, and the Interaction contract says "path-length stroke draw" without acknowledging it requires JS-driven inline styles. | Add an implementation note to `SankeyChart.Interaction.md §4` documenting that path-draw animation requires imperative DOM measurement (`getTotalLength()` in `useEffect`) and inline `style` overrides — it is NOT expressible as Tailwind classes. Consider simplifying the animation to `opacity: 0 → 1` (CSS-only, expressible as `transition-opacity`), which avoids the JS dependency for a similar perceived effect. |
| SI-6 | Medium | Gantt | `Gantt.Styling.md §1` places `sticky top-0 z-10` on the timeline header row (§2) inside a right pane that is `overflow-x-auto overflow-y-auto`. `position: sticky` does not work when the scroll container is the element with both `overflow-x` and `overflow-y` set — the browser treats the sticky element as being contained by the scrolling ancestor with `overflow` set on BOTH axes, breaking the sticky behavior entirely. The timeline header will scroll away with the content rather than remaining fixed. This is a well-known CSS layout trap. | The spec needs a layout revision: either (a) separate the horizontal scroll container from the vertical scroll container (common pattern: fixed header row outside the scroll container, synchronized via `scrollLeft`), or (b) use `position: sticky` in a container with only `overflow-x: auto` and no `overflow-y` set, and manage vertical scroll separately. Document this in `Gantt.Styling.md §2` as a known implementation constraint. |
| SI-7 | Medium | SankeyChart | `SankeyChart.Styling.md §4` specifies SVG text truncation via `SVG textLength / CSS overflow: hidden`. `CSS overflow: hidden` has no effect on SVG `<text>` elements — SVG text overflow is controlled by SVG-native mechanisms (`text-overflow` is not a valid SVG property; `clip-path` or `clipPathUnits` must be used). `textLength` attribute compresses/stretches the glyph spacing to fit a width but does NOT truncate — it distorts. Neither mechanism produces a readable ellipsis truncation. | Replace with a clip-path approach: define a `<clipPath>` per label region and apply `clip-path="url(#label-clip-N)"` on the `<text>` element. Or measure the text width programmatically and truncate the string with "…" in JS before rendering. Remove the reference to `CSS overflow: hidden` on SVG text as it is a no-op. |
| SI-8 | Medium | Upload | `Upload.Styling.md §6` uses `text-emerald-600` for success state text and file icon. `text-emerald-600` is a hardcoded Tailwind palette color, not a semantic design token. It will not respond to dark mode, user-configured theme changes, or the token override system the rest of the component uses (`hsl(var(--destructive))`, `hsl(var(--muted-foreground))`). This inconsistency also exists in `Upload.Accessibility.md §3` gap G-UPL5–8, which are accepted risks, but the styling inconsistency is a separate issue. The success state will have a fixed green that may conflict with the configured theme or fail dark-mode contrast. | Replace `text-emerald-600` with `text-success-foreground` (if a success token is defined) or derive a success token (`hsl(var(--success))`) consistent with the token system. If no success token exists yet, document as M2 tokenization backlog item at minimum, mirroring the explicit acknowledgment in `CopyButton.Styling.md §3` which explicitly flags this for M2 replacement. |
| SI-9 | Medium | Chat | `Chat.Styling.md §4` specifies typing indicator dots as `animate-bounce` with staggered delay via inline `style="animation-delay: 150ms"` etc. Tailwind v3 provides no `delay-*` utilities for the `animation-delay` CSS property (only `transition-delay` utilities exist as `delay-*`). Staggered `animate-bounce` delay requires either: (a) inline `style` props (works but not Tailwind-idiomatic and loses the `motion-reduce:` variant behavior), or (b) custom Tailwind config adding `animationDelay` utilities. The spec implies this is a pure Tailwind class but it is not achievable without inline styles or config extension. | The spec should explicitly document that staggered animation delay requires either inline `style` overrides for the delay or a Tailwind config extension (`theme.extend.animationDelay`). Add `motion-reduce:animate-none` to each dot's class list, consistent with the `Loader.Styling.md` pattern which already handles this correctly with `motion-reduce:animate-none`. |
| SI-10 | Medium | Sparkline | `Sparkline.Accessibility.md §3` specifies: the SVG carries `aria-describedby` pointing to the tooltip when visible. This creates a problematic dynamic: `aria-describedby` is resolved at the time AT reads the element, not on pointer-hover. Since the tooltip appears only on `mousemove`, an AT user on keyboard (or any non-hover session) will never trigger the tooltip, yet the spec implies the tooltip provides the accessible description. For keyboard users the `aria-describedby` reference will point to a hidden element, which AT silently ignores — but the intent is misleading. The tooltip mechanism is pointer-only (§4 explicitly says no keyboard navigation for Sparkline) which is consistent, but the `aria-describedby` wiring implies a describable element that is never available for AT users. | Either: (a) Remove `aria-describedby` since the tooltip is pointer-only and AT users rely solely on the `aria-label` summary (which is already the correct AT path per §1), or (b) add a `tabIndex={0}` focus mode that shows the nearest data-point value on keyboard focus, making `aria-describedby` meaningful. If (a), update §3 to say "tooltip is decorative for pointer users; AT users rely on `aria-label` summary." |
| SI-11 | Low | CircularGauge | `CircularGauge.Interaction.md §2` specifies "a CSS transition on the SVG transform" for needle rotation. CSS `transition` on SVG `transform` attribute is unreliable — the `transform` attribute uses SVG transform syntax (`rotate(angle cx cy)`) which is not interpolated by CSS transitions in all browsers. CSS transitions on SVG elements work reliably only on `transform` as a CSS property (not the SVG attribute), requiring `transform: rotate(Ndeg)` with `transform-origin` set appropriately. If the needle is positioned using `transform-origin` at the gauge center and uses CSS `transform`, this works; if it uses SVG `transform` attribute syntax, the transition silently breaks in Firefox < 112. | The spec should explicitly state the needle uses CSS `transform` property (not SVG `transform` attribute), with `transform-origin` set to the needle pivot point. Example: `style={{ transform: 'rotate(${angle}deg)', transformOrigin: '50% 100%' }}`. This is achievable but requires care and should be specified before implementation. |
| SI-12 | Low | DatePicker | `DatePicker.Accessibility.md §2` documents G-DP8: the 📅 emoji on the calendar toggle button is not `aria-hidden`. This is flagged as accepted-risk Low for M1. However, this is directly fixable with zero implementation cost (`aria-hidden="true"` on the emoji span or wrapping it in `<span aria-hidden="true">`). The accepted-risk disposition is disproportionate to the effort. Also, the emoji itself is the entire visible affordance for the calendar button — replacing it with an SVG icon would be a single-day task that eliminates the AT noise and is more token-theming-consistent (emoji color is not controllable via CSS). | Change disposition from Accepted-risk to Fix-in-M1 for G-DP8. At minimum, add `aria-hidden="true"` to the emoji span. Recommend replacing the emoji with an SVG calendar icon (`h-4 w-4`) consistent with the other form icons — this is zero API surface change and eliminates the AT issue entirely. |
| SI-13 | Low | MultiSelect | `MultiSelect.Interaction.md §1` specifies `setTimeout(150ms)` before focusing the search input after open. The 150ms timeout is a workaround for Radix popover focus animation, but it creates a testability problem: any test using `@testing-library/react` that expects the search input to be focused immediately after clicking the trigger will fail without a `vi.useFakeTimers()` + `act()` wrapper. This is a known class of React testing trap. The interaction spec documents the timeout but does not mention the test implication. | Add a note to `MultiSelect.Interaction.md §1` that the 150ms focus delay requires `useFakeTimers` + `act(async () => vi.advanceTimersByTime(150))` in tests. Alternatively, use the Radix `onOpenAutoFocus` callback (which fires after animation) instead of a raw timeout — this eliminates the arbitrary delay and makes behavior deterministic. |
| SI-14 | Low | StockChart | `StockChart.Semantic.md §5` specifies `StockIndicator[]` with types including "RSI" (Relative Strength Index). RSI is typically plotted in a separate sub-pane with its own y-axis scaled 0–100, not overlaid on the price chart. The Semantic contract does not define the `StockIndicator` interface, sub-pane layout, or how RSI's independent scale is handled. If RSI is implemented as a price-chart overlay (sharing the OHLC y-axis), the line will be visually meaningless (RSI values of 30–70 are invisible against a price range of e.g. $100–$200). This is an unresolved data model gap that will surface as a real implementation bug. | The `StockIndicator` interface needs a `pane?: 'main' | 'sub'` field and the layout spec must describe how sub-pane indicators get their own y-axis. Alternatively, explicitly scope M1 indicators to MA/EMA/Bollinger (main-pane overlays only) and move RSI/MACD to future-wave. |
