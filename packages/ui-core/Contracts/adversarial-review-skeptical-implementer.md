# Adversarial Review — Skeptical Implementer

**Date:** 2026-06-06
**Spec set:** packages/ui-core/Contracts/ (78-component reverse-spec set, post-batch-31 hardening)
**Perspective:** Skeptical Implementer — technically infeasible requirements in React 19 + TypeScript + Tailwind v4 + Radix UI + Vite?
**Prior review:** adversarial-findings-skeptical-implementer.md (2026-06-05, batch-31); that review's SI-1 through SI-14 are assumed applied. This review targets new surfaces and new cross-cutting issues not covered by the prior batch.
**Scope:** Interaction, Accessibility, and Styling contracts. Direct inspection of 5 .tsx implementation files. ~30 contract files read.

---

## Summary

The post-batch-31 spec set is substantially improved. No findings require blocking the current build wave. However, this review finds **3 High**, **8 Medium**, and **5 Low** new issues — none are regressions from batch-31 fixes, all are distinct from SI-1..SI-14. The most consequential cluster is a Tailwind v4 breaking-change issue that affects `focus:ring-*` and `focus:outline-none` recipes across dozens of form and navigation contracts (NI-1), a DOM/React rendering model mismatch in the `CommandPalette` and `TreeView` that renders the `role="combobox"` / `role="tree"` patterns non-conformant with the ARIA spec (NI-2, NI-3), and a timing dependency in `InlineEdit` that silently swallows edits under React 18+ Concurrent Mode batching (NI-5).

## Verdict

**Spec set is conditionally shippable.** No finding requires an immediate stop on current build work. However, three findings warrant high-priority spec amendments before the corresponding components ship to production:

1. **NI-1 (High — Tailwind v4 `focus:ring-*` without `focus-visible:`)**: Fleet-wide issue. File a mechanical sweep PR to update all affected Styling contracts before any form component goes to production. The Button.Styling.md contract is the canonical correct model; all others should align.

2. **NI-2 (High — CommandPalette `role="dialog" aria-modal` + no focus trap)**: Upgrade G-CPAL2 from "accepted risk" to "blocking before production use." The `aria-modal` declaration without a focus trap is not a missing enhancement — it is an AT trap that actively misleads screen reader users.

3. **NI-3 (High — TreeView `role="tree"` without roving tabIndex + arrow-key navigation)**: Upgrade G-TV1 + G-TV3 to co-blocking (same as the DatePicker G-DP1+G-DP5 precedent applied in batch-31). The `role="tree"` declaration promises a keyboard contract the implementation doesn't deliver.

The remaining findings (NI-4 through NI-15) are Medium/Low and should be filed as spec amendments in the next batch pass.
