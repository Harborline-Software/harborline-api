# Adversarial Review Round 3 — Pessimistic Risk Assessor

**Date:** 2026-06-06
**Perspective:** Pessimistic Risk Assessor — production bug finder
**Scope:** Feedback + DataDisplay categories (~35 components, ~140 files)
**Prior rounds read:** Yes — rounds 1+2 findings reviewed first

## Summary

Production risk level: **HIGH**. The Feedback + DataDisplay spec set ships with at least **five WCAG Level A failures** marked Accepted-risk M1 with no compensating "blocking before production use" note (TreeList tree semantics, Sortable keyboard reorder, ListBox keyboard navigation, Spreadsheet grid semantics, Filter form-control labels). It also contains **two structural authoring defects** that no rounds 1/2 finding flagged: (a) two complete EmptyState contract families coexist under Feedback/ and DataDisplay/ with the same reference implementation but divergent Accessibility specs, and (b) the Notification.Accessibility "error MUST NOT auto-dismiss" rule is contradicted by Notification.Semantic and Sonner.Semantic defaulting all variants to a 4000ms timer. Additional notable findings: NotificationBell uses `role="dialog"` with neither focus management nor Escape handling (broken dialog promise); ConnectionStatus uses the forbidden `role="status" + aria-live="assertive"` double-source pattern that Notification.Accessibility §2 expressly bans; MaskedText and QRCode emit sensitive values into `aria-label`, leaking PII into the accessibility tree; FreshnessBadge does not auto-update, so its "3m ago" text becomes a lie within minutes; and Round 1 RA-5's claimed "blocking before production use" note for Tooltip.Accessibility is still missing despite Round 2's FV-3 attesting it landed (a Round 1+2 fix verification failure).
