## Kill Trigger Assessment

**No kill trigger hit.** The 4-contract model remains structurally sound for in-DOM UI components (Devil's Advocate verdict). Three ADR 0017-A1 amendments are recommended at this scale (scope boundary clause, skip-contract convention, disposition tracking discipline) — none require halting spec work.

**MG3-7 flag — domain components in spec set:** 4 specs violate the fleet's `feedback_ui_react_no_domain_components` rule (PropertySelector, PropertyCard, RentIncreaseNotice, StatusPill). These require explicit disposition before M2 spec-tooling build.

## Structural Verdict (Devil's Advocate Round 3)

**The 4-contract model remains sound for interactive in-DOM UI components.** Sampled components (DataGrid, TextField, Switch, Dialog, Card, TabStrip, Alert, Tooltip, CircularGauge, Chat) all showed clean non-overlapping content distribution across the four contract types.

**Three amendments to ADR 0017-A1 are recommended:**

1. **Amendment A — Scope boundary clause:** Explicitly document what the 4-contract model does NOT cover. Add a `Trust-boundary` / `Compliance` section pattern (or a 5th contract) for components like RoleGate and ESignatureField whose primary contract surface is legal/security — not render behavior. The current model leaves these concerns scattered across prose.

2. **Amendment B — Skip-contract convention:** Permit a one-paragraph `<Contract>.md` file with `skip-rationale:` frontmatter for genuinely-N/A contract types (e.g., display-only components with empty Interaction), replacing forced 30+ line empty contracts.

3. **Amendment C — Disposition tracking discipline:** Drop the M1/M2 suffix convention (collapsed to noise); require `Tracked: <issue#>` for any deferred item; reclassify WCAG hard-failures on v1 components from `Accepted-risk M1` to `Blocking-before-v1-ship`.
