# Adversarial Review — Outside Observer

**Date:** 2026-06-06
**Spec set:** packages/ui-core/Contracts/ (78-component reverse-spec set)
**Perspective:** Outside Observer — can a new team member implement any component from specs alone?
**Sample:** 26 components read in depth (both Semantic + Interaction contracts); all 8 categories represented
**Components sampled:** Button, DataGrid, AutoComplete, ComboBox, CalendarDayPicker, AddressForm, Filter, FilterBar, ListToolbar, ColumnVisibilityMenu, SavedViewsMenu, Alert, ConfirmDialog, Dialog, ChunkProgressBar (alias), Chart, BarChart, AreaChart, Sankey, SankeyChart, AIPrompt, CommandPalette, TabStrip, SideNav, Card, RoleGate, MasterDetail, Gantt

---

## Summary

The high-quality tier of this spec set (M1 reverse-specs for shipping components and M2 forward-specs for Radix-foundation components) is genuinely implementable from the contracts alone. The prop tables are complete, defaults are explicit, state machines are provided, and known gaps are catalogued honestly. A competent React developer could implement Button, Dialog, DataGrid, Card, ConfirmDialog, FilterBar, ColumnVisibilityMenu, and SavedViewsMenu with no additional source-file lookups.

The problematic tier is the large class of **future-wave forward-specs** (DataVisualization, Scheduling, some AI), where cross-spec type references are undefined in-spec (e.g. `ChartBaseProps`, `ChartDataPoint`, `ChartSeries[]`), the "no implementation yet" note means the spec is aspirational rather than grounded, and the Recharts/D3 baseline is cited without enough depth to implement against. An implementer encountering these would need to read the referenced baseline libraries or hunt for the partially-defined shared types.

A secondary class of issues — present even in solid M1 contracts — involves missing FAILED conditions, jargon without context (`manualSorting`, `OnChangeFn<T>`, `asChild`/Radix conventions), and cross-spec references to `FormFieldContext` / `SavedViewsStore` without import paths.

**Overall verdict: CONDITIONAL PASS** — M1/M2 grounded components pass; future-wave forward-specs fail the Outside Observer test.

## Verdict

**CONDITIONAL PASS**

The 30–35 components with grounded M1 reverse-specs (DataGrid, Button, Dialog, ConfirmDialog, Alert, FilterBar, ColumnVisibilityMenu, SavedViewsMenu, ListToolbar, CalendarDayPicker, AddressForm, ComboBox, Filter, Chart/Sankey as shipped, etc.) pass the Outside Observer test. A competent React developer could implement any of these without reading source code, aided by complete prop tables, explicit defaults, state machines, and honest known-gaps catalogues.

The approximately 40 future-wave forward-specs in DataVisualization, Scheduling, and parts of AI fail the test. They reference undefined shared types (`ChartBaseProps`, `ChartSeries`, `ChartDataPoint`), defer implementation detail to the cited library's own docs (Recharts, D3, DHTMLX Gantt), and carry Interaction contracts that say "None identified — validate in M2" for components that do not yet exist. These cannot be implemented from specs alone.

**Structural patterns that recur across many specs and should be addressed systematically:**

1. **Unresolved Open Questions on Accepted specs** — TabStrip (6 questions), Button (6 questions). Resolution gates should precede the "Accepted" status flip.
2. **Gap registry is decentralized** — G-BT*, G-CR*, G-DG* references throughout contracts with no central lookup. A gap-registry document (or links to a single source) would let implementers find all outstanding issues.
3. **Cross-spec type references without paths** — `ChartBaseProps`, `FormFieldContext`, `SavedViewsStore`, `useFormField()`, `FilterOp`. Each should include an import path or a "defined in X.md" cross-link.
4. **Telerik legacy props carried without semantic meaning** — `fillMode`, `rounded`, `size` using `'small'|'medium'|'large'` appear in AutoComplete and ComboBox with no Meaning column. The spec notes their Telerik origin but gives no mapping to Harborline visual/structural behavior.
