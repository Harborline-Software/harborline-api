# Adversarial Review — Devil's Advocate

**Date:** 2026-06-06
**Spec set:** packages/ui-core/Contracts/ (78-component reverse-spec set, ~239 full 4-contract sets + 17 Semantic stubs = 256 components catalogued)
**Perspective:** Devil's Advocate — does the 4-contract model hold up at scale?
**Scope:** Sampled 40+ components across all 9 categories; audited line-counts for all 239 Interaction and Accessibility contracts; cross-referenced focus-ring, keyboard, and animation coverage.

---

## Summary

The 4-contract model (Semantic + Interaction + Accessibility + Styling) holds up well across the majority of the 239 fully-specified components. The split is earning its cost in the complex components (Dialog, DataGrid, TabStrip, SelectField, Button) where the four documents genuinely own non-overlapping surfaces. Four structural problems emerge at scale, however — none fatal, all correctable without changing the model.

**Key findings:**

1. **Keyboard tables are duplicated verbatim across Interaction and Accessibility in 31 components.** This is the most actionable problem: it creates divergence risk (one table gets an amendment, the other doesn't) and misleads implementors about which is authoritative.
2. **Focus ring and reduced-motion are split-ownership across 34 and 5 components respectively.** Styling owns the token; Accessibility owns the WCAG citation; neither says which file is authoritative when they conflict.
3. **24 Interaction contracts are substantively empty (sub-25-line "display only" declarations)** — they are correct and honest, but the file still costs the reader a navigation step to discover that fact.
4. **17 components have Semantic-only stubs** — 9 are headless out-of-scope utilities (correct posture), 8 are alias redirects (correct), and 1 (ESignatureField) claims all 4 companions in its header but only the Semantic exists — a broken-link contract.

The model does NOT need a 5th contract type at this scale. Where animation or state-machine concerns arise (Scheduler, Gantt, CircularGauge, Chat), the Interaction contract already absorbs them — and the existing AnimationContainer out-of-scope decision makes this explicit policy. Adding a dedicated Animation or StateMachine contract would produce yet more thin files for 90% of components that have trivial or no animation.

## Structural verdict

**The 4-contract model is sound and should not be amended at the structural level.** The findings above are calibration issues, not model failures:

- DA-1 and DA-2 are authorship-clarity gaps, not model redundancy. The Interaction vs. Accessibility split is correct; the split merely lacks explicit authority declarations for the crossover concerns (keyboard tables, focus rings). A one-line cross-reference convention fixes both.
- DA-3 is a communication/tooling gap, not a design gap. Display-only Interaction contracts ARE correct content — they close the set and record a deliberate design decision.
- DA-4 through DA-7 are mechanical hygiene issues solvable by local convention, not model restructuring.

**The model does NOT need a 5th contract type.** The three candidate surfaces for a 5th contract are:

1. **Animation contract** — Rejected. Animation is partitioned correctly today: Interaction owns the trigger and timing (when and how long), Styling owns the token surface (what CSS class/variable), Accessibility owns the WCAG gate (does it suppress under `prefers-reduced-motion`). Merging into a 5th file would create a 5-way split for a concern that naturally distributes across three. The out-of-scope decision on AnimationContainer settles this as deliberate policy.

2. **State machine contract** — Rejected. The three most stateful components (Scheduler, Gantt, Spreadsheet) fit their state machines cleanly inside their Interaction contracts: Scheduler §1–7 covers navigation/view-switch/event-CRUD/keyboard; Gantt §1–7 covers task interactions; Spreadsheet §1–5 covers cell selection/edit/commit/cancel/delete. The state machines are 3–8 states and are readable inline. A separate State Machine file would be meaningful only for a component with 15+ states and branching on async events — nothing in the current 239-component set reaches that threshold.

3. **LLM behavior contract** — Rejected. AI components (Chat, AIPrompt, PromptBox, SmartPasteButton) have their streaming/message-state behavior in Interaction and their ARIA live-region obligations in Accessibility. The LLM behavior (model selection, retry, streaming cursor, auto-scroll) is correctly in Interaction §1–5. A separate LLM contract would duplicate the streaming-state coverage.

**The two highest-priority changes:**

1. Adopt an explicit **authority-declaration convention** for cross-contract concerns (keyboard tables → Interaction authoritative; focus ring token → Styling authoritative, Accessibility gatekeeper; reduced-motion mechanism → Styling, obligation → Accessibility). This should be documented in an ADR 0017 amendment and applied in the next amendment wave.

2. Add `interaction-class: display-only | interactive | container | headless` to the Semantic contract frontmatter. This surfaces in tooling (completeness scanners, implementation generators) and removes ambiguity about whether a thin Interaction contract is correct or incomplete.

---

## Verdict

**The 4-contract model holds up at scale.** 239 full 4-contract sets covering 9 component families from trivial badges (2 lines of interaction) to complex data grids (200+ lines per contract) — the model spans that range correctly by design. The thin contracts are not waste; they are intentional scope declarations. The split concerns (keyboard/focus ring/reduced-motion) are resolvable by convention rather than restructuring. File the authority-declaration convention as an ADR 0017 amendment before the next major authoring wave to prevent compounding the DA-1/DA-2 drift risk.
