# Adversarial Review Round 3 — Outside Observer

**Date:** 2026-06-06
**Perspective:** Outside Observer — new senior React engineer joining the team
**Scope:** DataEntry category (~93 components, 351 contract files)
**Prior rounds read:** Yes — Rounds 1+2 hardening logs read in full; deferred items tracked

## Summary

The DataEntry contracts are usable as starting implementation guides for senior implementors but contain three categories of trap: (a) **systematic catalog-row metadata rot** — 14 of 16 spot-checked components have catalog-row numbers pointing at unrelated components; (b) **broken inter-contract API surface coherence** — at least three contracts consume `{ id }` from `useFormField()` but the canonical `FormFieldContextValue` declares only `{ describedBy?: string }` — TypeScript compile error on the critical accessibility mechanism; (c) **navigation/discovery gaps** — 29 Semantic files self-reference themselves as companion contracts, and 10 Field-pattern specs list companion contracts as bare text with no links. A new engineer can build TextField/NumberField/SelectField/CheckboxField as-spec'd; the surrounding catalog hygiene and the TextBox/TextField/Input/FieldWrapper tangle will erode spec trust within the first afternoon.

## Key takeaways

1. **OO3-1 (FormFieldContextValue API shape) is the single highest-priority fix** — TypeScript compile error on the accessibility mechanism used by the entire Batch B field family.
2. **MG-3 metadata rot (OO3-8/OO3-9) is now actively eroding implementor trust** — 14 of 16 spot-checked components have wrong catalog rows. Escalate from "QM sweep eventually" to "block M2 start."
3. **OO3-6/OO3-7/OO3-16 (companion contract navigation) is mechanically fixable in one PR** — ~50 line changes across 40 files; highest reward-per-effort cleanup available.
4. **TextBox/TextField/Input tangle (OO3-19 + Round 1 MG-5) needs council ratification** to designate a canonical primitive and demote the others to alias stubs.
