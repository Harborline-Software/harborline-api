# Adversarial Review Round 3 — Pedantic Lawyer

**Date:** 2026-06-06
**Perspective:** Pedantic Lawyer — terminology and consistency enforcer
**Scope:** AI (6 components / 24 files) + DataVisualization (~32 components / ~128 files) + Navigation (~22 components / ~88 files) + Scheduling (5 components / 20 files) = ~65 components, ~260 files
**Prior rounds read:** Yes — Round 1 (88 findings) + Round 2 (29 findings) reviewed. Findings below are NEW or escaped prior batches.

## Summary

Round 3 surfaces 19 new terminology/consistency findings. Five are HARD gap-ID collisions across distinct components (parallel to PL-1..PL-6 in Round 1) that survived the Round 1/2 sweeps. Eight are prop/callback naming divergences inside single category families (parallel to PL-7..PL-10). Six are intra-component naming-format inconsistencies (suffix-A vs no-suffix in same component's 4-contract set). The PL-8 AI-family `onSubmit` standardization missed PromptBox, where `onPromptRequest` still survives. The DA-1 SHA-pinning intent for alias contracts was implemented without the SHA, leaving the drift-detection unsatisfied. Two non-canonical Known Gaps heading variants exist that the prior rounds did not catch.

## Patterns identified

1. **Gap-ID prefix collisions persist** after Round 1's PL-1..PL-6 sweep. PL3-1 (Wizard×2), PL3-2 (Sankey×2), PL3-3 (Pagination/Pager) all qualify as the same severity class — distinct components sharing a prefix. A recurring root cause: when a component is duplicated in two categories (Navigation/Wizard vs DataEntry/Wizard) or has a reverse-spec impl + forward-spec stub (Sankey + SankeyChart), both branches independently claim the natural prefix.

2. **Intra-component gap-ID format divergence** (PL3-14..PL3-17) emerges when Interaction is authored first with sequential numbers (G-GANTT1) and Accessibility is authored later with contract-suffix format (G-GANTT-A1). Same component, two formats, in the same 4-contract set. Affects ChartWizard, Scheduler, Gantt, TaskBoard, ActionMenu. Recommend pinning the contract-suffix format (G-X-I1 / G-X-A1 / G-X-S1) since Accessibility/Styling have already drifted toward it.

3. **AI family standardization missed PromptBox** (PL3-4, PL3-5). PL-7 + PL-8 standardized callback names and suggestion-object shape across AIPrompt/Chat/InlineAIPrompt — PromptBox was authored implementation-first (#A0-class reverse-spec) and silently retained `onPromptRequest` + `string[]` suggestions. Same fix template as FV-1 from Round 2: scan the family for any holdouts.

4. **`ChartBaseProps` is a load-bearing fiction** (PL3-7). Nine charts extend it; nobody defines it. Each consumer inline-comments the (presumed) field list with the consumer's understanding — guaranteed to drift. Architecturally PL3-18 follows: even forward-spec roots that don't currently extend ChartBaseProps duplicate the same field set inline. Both are symptoms of the same missing canonical definition.

5. **DA-1 SHA-pin promise vs `Aliases-canonical:` reality** (PL3-19). Round-1 fix substituted a markdown link for a SHA pin without amending the disposition note. The drift-detection that DA-1 cited as the rationale is not in place.
